Teacher Guide

Vercises

An Exercism-style platform for Verilog exercises. Students open a browser, read the spec, write RTL in a Monaco editor, hit Run, and see simulator output and waveforms — no local toolchain needed.

As a teacher, your only job is to drop files into a folder and write a config.json. Everything else is handled by the platform.

Monaco editor (multi-tab) iverilog / verilator Yosys synthesis Surfer waveform viewer KaTeX math in instructions Docker-compose deploy

Getting Started

  1. 1

    Clone the repository

    git clone https://github.com/Lawrence-lugs/Vercises.git
cd Vercises
  2. 2

    Build and start the stack

    docker compose build
docker compose up

    This starts a Node.js server (port 3000) behind a Traefik reverse proxy, and a Vite-based React client (port 5173). Exercises are volume-mounted at /app/exercises — no rebuild needed when you add content.

  3. 3

    Open the app

    http://localhost/exercises

    The exercise list is auto-generated from the folders inside exercises/.

Adding an Exercise

An exercise is just a folder inside exercises/. The folder name becomes the exercise's URL slug and display title. The minimum required content is one Verilog file and a testbench.

Minimum folder layout

exercises/
└── my-exercise/
    ├── my_design.v        # student-editable design file
    └── tb_my_design.v     # testbench (can be hidden from the editor)

That's it. The platform will detect the folder and list the exercise. Both files appear as editable tabs by default.

Recommended folder layout

exercises/
└── my-exercise/
    ├── my_design.v        # student edits this
    ├── tb_my_design.v     # hidden from editor
    ├── components.v       # optional helper files (also hidden)
    ├── instructions.md    # shown in the left pane
    └── config.json        # exercise configuration (see below)

Writing instructions.md

This file is rendered as Markdown in the left pane, with full support for:

  • GitHub Flavored Markdown (tables, code blocks, task lists)
  • Inline and block LaTeX math via KaTeX
  • Images — place image files in the same folder and reference them by filename

config.json Reference

All fields are optional. Omit the file entirely for a zero-config exercise.

Full example

{
    "hidden":             ["tb_my_design.v", "components.v"],
    "simulation_command": "iverilog tb_my_design.v components.v my_design.v",
    "default_args":       "",
    "enable_args":        false,
    "run_command":        "./a.out",
    "hide_instructions":  false,
    "allow_new_files":    false
}
Field Type Default Description
hidden string[] [] List of filenames to hide from the Monaco editor. Hidden files are still compiled — students just can't see or modify them. Use this for testbenches and pre-built component libraries you don't want tampered with.
simulation_command string "iverilog" The compile command that is run on the server. Can include full filenames and flags. When enable_args is false, this is the complete command — the args box is disabled and hidden. Set to "yosys-then-ivlog" to synthesize before simulating (see yosys-then-ivlog).
default_args string "" Pre-filled text in the args input box. Useful when enable_args is true and you want to give students a starting hint (e.g. the expected filename order) without hard-coding it into the command.
enable_args boolean true When true, an args input box is shown so students can pass extra flags or filenames to the simulator. Set to false to lock the simulation command entirely — ideal for guided exercises where the command is fully specified in simulation_command.
run_command string "./a.out" Command executed after a successful compile step. Change this if you use a custom output name via -o, or if you're using Verilator (which produces a different binary path).
hide_instructions boolean false When true, the left instructions pane is collapsed and hidden. Useful for open-ended "sandbox" exercises where there is no fixed specification.
allow_new_files boolean false When true, students can create additional Verilog files directly from the editor UI (a + New File tab appears). Useful for freeplay-style exercises or any exercise where students are expected to design their own module hierarchy.

yosys-then-ivlog

yosys-then-ivlog is a drop-in replacement for iverilog that adds a Yosys synthesis step before simulation. It accepts the same arguments and exits with the same codes.

Why use it?

Verilog is a dual-purpose language: valid simulation code is not necessarily synthesizable RTL. A student could write behavioral constructs — blocking assignments in always blocks, implicit latches, unsupported operators — that pass a behavioral testbench but would fail in a real ASIC or FPGA flow.

When you set simulation_command to "yosys-then-ivlog", the platform:

  1. 1. Passes the design sources through Yosys synthesis (synth -flatten), generating a gate-level netlist. If the design is not synthesizable, Yosys exits with an error — the student sees that immediately.
  2. 2. Passes the gate-level netlist (plus Yosys's own simlib.v cell library) to iverilog for simulation. The testbench runs against the synthesized gates, not the behavioural model.

The student sees the synthesis log in the output pane, followed by simulation results — all in one click.

Testbench separation with --

Testbenches must not go through Yosys (they use simulation-only constructs like $display and $dumpfile). Pass them after a -- separator so they are forwarded directly to iverilog, bypassing synthesis: 

yosys-then-ivlog  my_design.v  --  tb_my_design.v

Files before -- → synthesized by Yosys → gate-level netlist.
Files after -- → passed directly to iverilog alongside the netlist.

config.json for a gate-level exercise

{
    "hidden":             ["tb_my_design.v"],
    "simulation_command": "yosys-then-ivlog my_design.v -- tb_my_design.v",
    "enable_args":        false,
    "run_command":        "./a.out"
}

Supported flags

Flag Behavior
-s <top> Sets the hierarchy top module for Yosys. Not forwarded to iverilog.
-o <file> Output binary name, forwarded to iverilog.
-D, -I Preprocessor defines and include paths — forwarded to both Yosys and iverilog.
-- Separator. Files after this go to iverilog only (testbenches, models).
other flags Forwarded verbatim to iverilog.

Exercise Patterns

Mix and match the config options to create different exercise styles.

Guided / Autograded

The testbench is hidden. The simulation command is fixed. Students only see and edit their design file. A pass/fail is determined by the testbench output. 

{
  "hidden":             ["tb_alu.v", "components.v"],
  "simulation_command": "iverilog tb_alu.v components.v alu.v",
  "enable_args":        false,
  "run_command":        "./a.out"
}
Gate-Level Verification

Design sources are synthesized by Yosys before simulation. Students must write synthesizable RTL — behavioral workarounds fail at the synthesis step. 

{
  "hidden":             ["tb_design.v"],
  "simulation_command": "yosys-then-ivlog design.v -- tb_design.v",
  "enable_args":        false,
  "run_command":        "./a.out"
}
Discovery / Partially Guided

The simulation command base is set but the args box is enabled with a hint. Students must figure out which files to include — part of the exercise. 

{
  "simulation_command": "iverilog",
  "enable_args":        true,
  "default_args":       "tb_stack.v ???.v",
  "run_command":        "./a.out"
}
Freeplay / Sandbox

No instructions pane. Students can create new files, write anything, and run arbitrary simulations. Good for open-ended projects or end-of-unit labs. 

{
  "simulation_command": "iverilog",
  "enable_args":        true,
  "hide_instructions":  true,
  "allow_new_files":    true,
  "run_command":        "./a.out"
}

Waveform viewer included

If your testbench produces a .vcd file (via $dumpfile / $dumpvars), Vercises automatically opens it in the embedded Surfer waveform viewer after simulation. No extra configuration needed.
