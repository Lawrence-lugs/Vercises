Architecture Reference

System Architecture

Vercises runs user-submitted Verilog in fully isolated, ephemeral Docker containers — one per simulation request. Each container is created from scratch, given no network access, no privilege escalation path, and a hard-capped lifetime of 30 seconds, then destroyed.

React + Vite (client) Node.js / Express (server) dockerode (Docker SDK) vercises-sim image (EDA tools) Traefik (reverse proxy) Surfer (WASM waveform viewer)

Container Security Model

Every simulation container is spawned with the following constraints. None of these are optional — they are hardcoded in server/simulator.js and cannot be overridden by exercise config or user input.

Flag Value Effect
NetworkMode 'none' No network interfaces at all — no loopback, no internet, no intranet
ReadonlyRootfs true Container root filesystem is immutable; writes only allowed in /workspace (bind) and /tmp (tmpfs)
CapDrop ['ALL'] All Linux capabilities dropped; no raw sockets, no mounts, no kernel module loading
SecurityOpt ['no-new-privileges'] Blocks privilege escalation via setuid/setgid binaries
Tmpfs /tmp noexec, nosuid, 64 MB Tools can write temp files but cannot execute binaries from /tmp, and total /tmp is capped
Memory 256 MB Hard memory cap; process is OOM-killed if exceeded
NanoCpus 0.5 CPUs CPU share limit; prevents monopolising the host under load
PidsLimit 64 Fork bomb mitigation; total process count inside the container is capped
User '1000:1000' Runs as non-root user sim; UID 1000 owns no host resources
Kill timeout 30 s Container.kill() is called after 30 s regardless of state; prevents runaway simulations

Command Injection Prevention

simCmd and runCmd are split into an argv array and passed directly to docker.createContainer({ Cmd: argv }) — never through a shell. Shell metacharacters such as ; & | ` $( ) are inert.

simCmd whitelist

  • iverilog
  • yosys-then-ivlog

First token only. Anything else → HTTP 400.

runCmd whitelist

  • vvp

./a.out is intentionally blocked. The compiled binary lives on a bind-mounted directory that inherits noexec from the host filesystem; exec()-ing it would fail. vvp a.out reads the iverilog output as bytecode data — not as an exec()-ed binary — so noexec does not apply, and no user-compiled ELF is ever exec()-ed by the OS.

⚠ Docker Socket Trade-off

Mounting /var/run/docker.sock into the server container gives the server process effective root on the host — a compromised server could spawn arbitrary containers. For public deployments, consider wrapping the socket with Tecnativa/docker-socket-proxy to allow only the container lifecycle endpoints the server actually needs (POST /containers/*, DELETE /containers/*).

Server Internals

File Map

File Role
server/index.js Express app — defines all HTTP routes. The POST /api/simulate handler now delegates entirely to simulator.js
server/simulator.js Container orchestrator — input validation, concurrency gate, per-request temp dir, two-stage container lifecycle, artefact collection, cleanup
server/listExercises.js Filesystem scan — returns a list of exercise directory names
server/yosys-then-ivlog Bash script — wraps Yosys synthesis + iverilog gate-level simulation. Copied into vercises-sim image at build time
sim/Dockerfile Defines vercises-sim:latest — Debian bookworm-slim + iverilog + yosys + non-root UID 1000. No Node.js.
server/Dockerfile Defines the Express server image — Node.js only. EDA tools removed; the server no longer runs them directly.

API Endpoints

Method Path Description
GET /api/exercises List all exercise names (directories under exercises/)
GET /api/exercise/:id Return files, instructions, and config for one exercise. Hidden files are included in the payload (used by the simulation command).
POST /api/simulate Run a simulation. Returns { output, vcd, vcd_content, netlist_content }. Returns 400 on invalid commands, 429 when at concurrency limit.

POST /api/simulate — Payload & Response

Request body (JSON)

{
  "files": [
    { "name": "alu.v",    "content": "..." },
    { "name": "tb_alu.v", "content": "..." }
  ],
  "simCmd": "iverilog tb_alu.v alu.v",
  "runCmd": "./a.out"
}

Response body (JSON)

{
  "output": "...",
  "vcd": "counter.vcd",
  "vcd_content": "$timescale ...",
  "netlist_content": "module ... (yosys)"
}

Variable Default Description

MAX_CONCURRENT_SIMS 5 Max simultaneous simulation requests. Excess requests receive HTTP 429.

Deployment

Container Map

Container Image Lifetime Notes
vercises-client node:20-bullseye (Vite) Persistent Serves React SPA + Surfer WASM via Vite dev server. Exercises volume mounted as static assets.
vercises-server node:20-bullseye Persistent Express API. Holds docker.sock mount and /tmp bind. No EDA tools installed.
vercises-sim (×N) vercises-sim:latest Ephemeral (~seconds) Spawned per simulation request. Debian slim + iverilog + yosys. Hard-killed after 30 s. Removed on exit.

Build & Run

The simulation image must be built before starting the stack for the first time (or after updating EDA tool versions). Because vercises-sim uses the build-only profile, it is not started by docker compose up — only built. 

# Build both the server image and the simulation image
docker compose -f docker-compose.local.yml build

# Start the stack (client + server only; sim containers are ephemeral)
docker compose -f docker-compose.local.yml up

For production with Traefik:

docker compose build
docker compose up -d
